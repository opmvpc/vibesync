# VS-034 — job CI client-macos (phase 5 ADR-010)

*2026-08-07. YAML écrit par un agent Sonnet (2 stalls sur l'exécution locale des
commandes — travail YAML récupéré tel quel), vérification et bureaucratie par
l'orchestrateur.*

## Ce que fait le job

`client-macos` (runs-on: macos-latest), trois étapes, aucune dépendance des
jobs existants :

1. `./scripts/test-core-macos.sh` — suite C portable (878 vérifications,
   13/13 vecteurs) sous asan+ubsan, clang d'Xcode.
2. `swift test` — 41 tests (vecteurs via wrapper CoreEngine ET via API C).
3. `./scripts/build-macos.sh` + garde-fou budget : échec si le bundle dépasse
   10 240 Ko (ADR-007). Mesuré au moment de l'écriture : 1 124 Ko.

Le job `release` ne dépend PAS de `client-macos` : les releases n'embarquent
que l'exe Windows aujourd'hui. Ajouter le .app aux releases est un chantier
séparé (signature/notarisation à trancher : la signature ad hoc actuelle
suffit entre amis avec `xattr -d com.apple.quarantine`, pas pour une
distribution large).

## Vérifications locales (orchestrateur)

- Les 3 commandes passent depuis le checkout (dernier passage : 878 checks,
  41/41, bundle 1 124 Ko < 10 240).
- YAML validé (parsing OK), jobs existants intacts.
- Coût : runner macOS ~10× Linux ; un seul job, pas de matrice, ~3-4 min
  attendues.

## À confirmer

Premier run vert du job sur GitHub (seule chose invérifiable localement :
l'environnement macos-latest — versions Xcode/Swift du runner).
