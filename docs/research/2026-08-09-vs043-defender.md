# VS-043 — Faux positif Defender : soumission Microsoft et options de signature

*2026-08-09 — procédure opérationnelle + étude coût/bénéfice de la signature de
code. Déclencheur : `vibesync.exe` v0.2.3 supprimé au téléchargement chez un ami
(`Trojan:Win32/Wacatac.C!ml`).*

## 1. Ce qui se passe, en une phrase

`!ml` = détection par **modèle d'apprentissage automatique côté cloud**, pas par
signature d'un malware connu. Le modèle juge un faisceau d'indices, et vibesync
les coche à peu près tous : binaire **non signé**, **très petit** (264 Ko, un
profil de dropper/stager), **prévalence quasi nulle** (quelques dizaines de
téléchargements au monde), **hash neuf à chaque release**, **trafic réseau
sortant** (WinHTTP/WebSocket) et **pilotage d'un autre processus** (VLC). Aucun
de ces traits n'est corrigeable sans trahir le projet — sauf deux : les
métadonnées et la signature.

Conséquence structurelle : **chaque release repart de zéro**. L'autorisation
locale de l'utilisateur et le verdict Microsoft portent sur un hash ; un nouveau
`.exe` est un inconnu. La seule chose qui casse ce cycle est une signature de
code (la réputation se rattache alors au certificat, pas au fichier).

## 2. Ce qui a été fait dans cette itération (0 €)

1. **VERSIONINFO complet** dans `ui/win32/vibesync.rc` (CompanyName,
   FileDescription, ProductName, InternalName, OriginalFilename,
   LegalCopyright, Comments avec l'URL du dépôt, File/ProductVersion tirées du
   fichier `VERSION`). Un bloc de métadonnées vide est un signal négatif connu
   des heuristiques ; ce n'est pas une garantie, c'est le levier gratuit.
2. **Encadré dans `docs/guide-amis-windows.md`** : pourquoi l'alerte, comment
   restaurer depuis l'historique de protection, et la mention explicite que
   l'opération peut être à refaire à chaque version.
3. **Soumission Microsoft** — procédure ci-dessous, à rejouer à chaque release.

## 3. Soumettre le faux positif à Microsoft — pas à pas

**Portail** : <https://www.microsoft.com/en-us/wdsi/filesubmission> (WDSI —
Windows Defender Security Intelligence ; c'est le canal grand public/éditeur,
distinct de `security.microsoft.com/submission` qui, lui, demande un tenant
Defender for Endpoint).

À rejouer **après chaque publication de tag**, une fois l'asset disponible sur
la page des releases.

1. **Se connecter** avec un compte Microsoft (personnel suffit). Sans connexion
   la soumission part en anonyme, sans historique ni notification de verdict :
   se connecter, toujours.
2. **Type de client** : choisir **« Software developer »** (et non « Home
   customer » / « Enterprise customer »). C'est le tri qui compte : ce choix
   route vers l'équipe qui traite les faux positifs d'éditeurs, la file la plus
   rapide.
3. **Fichier à soumettre** : **exactement l'asset publié**, celui que les amis
   téléchargent — `vibesync-<version>.exe` récupéré depuis la page GitHub
   Releases, pas le binaire local de `ui/win32/build/`. Les deux peuvent
   différer au bit près (toolchain, chemins de build) et donc au hash : c'est le
   hash publié qu'il faut faire blanchir.
   *Si le fichier fait plus que la limite du formulaire, le soumettre zippé sans
   mot de passe (ou avec `infected`, indiqué dans les notes).*
4. **Detection name** : `Trojan:Win32/Wacatac.C!ml` (recopier le nom exact
   affiché dans l'historique de protection — il varie d'une release à l'autre :
   `Wacatac.B!ml`, `Wacapew.C!ml`, `Puwaders.C!ml`…).
5. **Cocher / renseigner** :
   - **« Do you believe this file is incorrectly detected? » → Oui** (c'est la
     case qui qualifie la soumission en faux positif) ;
   - **produit concerné** : Microsoft Defender Antivirus ;
   - **version des définitions** : celle affichée dans Sécurité Windows →
     Paramètres de protection contre les virus (« Version du renseignement de
     sécurité ») sur la machine qui a détecté ;
   - **URL de provenance** : le lien direct de l'asset GitHub Releases ;
   - **« Additional information »** : texte réutilisable —
     > Open-source Windows client (single unsigned executable, ~264 KB,
     > non-commercial hobby project). Source code and build pipeline are public:
     > https://github.com/opmvpc/vibesync — the released .exe is produced by
     > GitHub Actions from that repository (workflow .github/workflows/ci.yml).
     > The program synchronises video playback between friends: it drives a
     > locally installed VLC through its HTTP interface and talks to a
     > self-hosted WebSocket server. It does not install anything, does not
     > persist, and does not download or execute code. The detection is a
     > machine-learning false positive on a low-prevalence unsigned binary.
6. **Envoyer**, noter l'**identifiant de soumission**. Le suivi se fait dans
   l'onglet **Submission history** du portail.
7. **Délai** : verdict en général sous 24-72 h ; en cas de blanchiment, la
   correction se propage par les définitions cloud (effet quasi immédiat côté
   client, sans mise à jour manuelle).

**Pièges connus** (rapportés régulièrement sur les forums Microsoft en 2026) :
la page de détail d'une soumission peut afficher « details not found or expired »
alors que la soumission est bien en cours — se fier au statut de la liste ; et
un verdict « ne correspond pas aux critères de malware » ne garantit pas que la
détection cloud disparaisse partout immédiatement. Vérifier sur
[VirusTotal](https://www.virustotal.com/) 48 h après (le moteur « Microsoft » doit
passer au vert) et, si la détection persiste, re-soumettre en citant
l'identifiant précédent.

**Complément gratuit et utile** : soumettre aussi le `.exe` publié à VirusTotal
à chaque release. Cela crée une trace publique, sert de preuve aux amis
inquiets, et alimente la prévalence — le facteur qui fait le plus baisser le
score heuristique avec le temps.

## 4. Options de signature — synthèse coût/bénéfice

| Option | Coût | Effet sur Defender/SmartScreen | Faisabilité ici |
|---|---|---|---|
| **Statu quo + soumission WDSI** | 0 € | Corrige *a posteriori*, release par release. N'empêche ni SmartScreen ni la première alerte. | Immédiate, déjà en place |
| **Azure Trusted Signing** (rebaptisé **Azure Artifact Signing**) | ~9,99 $/mois (offre Basic, 5 000 signatures/mois) | Authenticode complet ; réputation attachée au certificat, donc **cumulative entre versions**. SmartScreen se calme après un temps de chauffe. | **Bloquée** : depuis avril 2025 l'inscription est réservée aux **organisations US/Canada justifiant 3 ans d'existence vérifiable** ; l'onboarding des développeurs individuels reste suspendu (public preview). Non éligible depuis la France. |
| **Certum Open Source Code Signing** (carte à puce + lecteur) | ~85-115 € la première année (kit matériel + certificat), ~30 €/an ensuite | Même bénéfice Authenticode. Certificat OV : SmartScreen exige quand même une phase de réputation (l'EV, qui l'évite, est hors de prix). | Réaliste : produit **conçu pour les développeurs open source individuels**, ouvert hors US. Mais **matériel physique** → signature manuelle sur le poste de Thibault, donc **incompatible avec la signature automatique en CI** telle que le pipeline est fait aujourd'hui (ou alors variante « cloud » de Certum, plus chère). |
| **Certificat OV classique** (DigiCert, Sectigo…) | 200-400 €/an | Idem. | Hors sujet pour un projet gratuit entre potes. |

*(Tarifs relevés en août 2026, à revérifier au moment de décider — ce marché
bouge vite, et les règles d'éligibilité de Trusted Signing ont déjà changé deux
fois en dix-huit mois.)*

## 5. Recommandation

**Rester à 0 € pour l'instant** — décision Thibault.

Raisons : (a) la seule option qui s'intégrerait proprement à la CI (Trusted
Signing) **nous est fermée par ses critères d'éligibilité**, ce n'est donc même
pas un arbitrage de prix ; (b) Certum coûte peu mais ré-introduit une **étape
manuelle avec un jeton matériel** à chaque release, ce qui va à l'encontre du
pipeline actuel « tag → GitHub Actions → assets » ; (c) le public est une
poignée d'amis à qui l'on peut expliquer la manip une fois, guide à l'appui ;
(d) même signé OV, SmartScreen continuerait d'avertir tant que la réputation
n'est pas construite — le gain visible serait partiel.

**Routine de release à adopter** (coût marginal ~5 minutes) :

1. publier le tag, attendre les assets ;
2. soumettre `vibesync-<version>.exe` à WDSI en « Software developer » ;
3. le déposer aussi sur VirusTotal ;
4. prévenir les amis, en pointant l'encadré du guide Windows.

**Ce qui ferait rouvrir le dossier** : un cercle d'utilisateurs qui dépasse les
amis proches, une soumission WDSI restée sans effet deux releases de suite, ou
l'ouverture de Trusted Signing/Artifact Signing aux développeurs individuels
hors US-Canada.
